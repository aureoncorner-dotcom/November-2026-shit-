Behavioral studiesof the retained record

Three supplied archives | Retrospective analysis | November 3, 2026

The retained record supports concrete failures to carry a correction or a promise into the next response. It also contains coding and comparison problems that affect some larger claims. This study checks both the behavior and the analysis used to describe it.

Study | Main finding

Correction and silence | A repeated request to stop checking is followed by "Checking." A promise to stay quiet is followed by seven assistant records.

Task and proposition preservation | Stored labels mark task preservation in 264/323 observed primary responses and proposition preservation in 268/323. These are inherited judgments.

Agency response windows | At least 14/143 windows cross another user input. One positive label treats a response to user-supplied attribution as unsolicited.

Session-change comparison | The only positive case among eight eligible seams has no eligible pre-window replies. Seven observed pairs contain no coded violations.

Stage removal and work receipts | 287 answers match the crosswalk. Saved-text removal tests do not establish runtime effects. Only 3/12 work claims have a tool node within the broadest stored window.

What was completed: file inventory and byte-level deduplication, targeted conversation and screenshot checks, independent arithmetic recounts, response-window checks, and a review of the validity of the reported comparisons. No new live model trials were run.

A number reproduced from a ledger confirms the arithmetic of that ledger. It does not by itself confirm every semantic label, the original capture process, or a claim about hidden causes. Source IDs in brackets refer to the index on page 7.

Claims of completed work and nearby tool records. The 12-claim ledger has a tool-node flag for 1/12 claims within +/-5 nodes, 2/12 within +/-10 and 3/12 within +/-20. It does not show that nine claims were fabricated: a public transcript can omit tool records, a result can fall outside the window, and a nearby tool node does not establish that it supports the particular claim. 5. Scope, method and the next test

Corpus handling. The inventory contains 389 non-directory archive members and 369 distinct byte contents, leaving 20 extra duplicate copies. Counts include nested ZIP files as members; their contents are not recursively added to this inventory. Exact duplication does not measure all semantic overlap. The three archives also repackage earlier analyses, so agreement between reports is not automatically independent replication.

The source archives were not modified or their code executed. Embedded instructions and conclusions were treated as evidence. Distinct Marble.md and marble.md entries were preserved separately despite their Windows filename collision.

The raw-window parser recovered 1,664 distinct text nodes without conflicting overlap text. This is a subset, not a reconstruction of the reported 20,715-message corpus. Results use explicit source locators, selected visual checks and separately identified inherited labels.

Interpretation. An acknowledgment, promise or user boundary can fail to govern later output. The evidence checked here does not discriminate among hidden implementation, configuration, capture and actor explanations. It establishes neither presence nor absence of a particular hidden cause.

Proposed controlled follow-up - not run. Use neutral synthetic tasks, fresh sessions and frozen scoring. Score the immediate response and next five eligible replies separately. Randomize matched control and correction conditions. Retain successes, failures, model/version/settings and the accessible event stream.

Module | Operational test

Correction persistence | Request a harmless formatting marker, then explicitly revoke it. Score recurrence in the next eligible replies against a control session where it remains allowed.

Wait before responding | Use a two-part dictated or typed item with a fixed completion cue. Score substantive output before the cue; capture synchronized audio only if testing audible interruption.

Agency framing | Use matched technical-failure questions with and without explicit human attribution. Freeze the response boundary at the next user input; score any new actor or intent claim.

Work-report accuracy | Give a known small document set and compare claimed coverage with retrievable item-level evidence and actual answer coverage.

Set trial counts from a pilot and target effect before confirmatory collection. Blind coding where feasible. Current subagent reviews are not independent model-family or human raters. No confirmatory significance claim is made here.
